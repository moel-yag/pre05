BSQ Tutorial

BSQ asks you to read a map, validate it, find the biggest square that avoids obstacles, draw that square with the full character, and print the result. This page explains the subject first, then focuses on the allowed functions with small examples that are not a complete BSQ solution.

Subject Map Format Validation Algorithm Functions Function Habits Workflow Mistakes

Goal

Replace empty cells with the full character to show the largest possible square.

...o..... xxxx..o.. xxxx..... xxxx.o... xxxx...o.
empty obstacle full

What BSQ Wants

Your program receives one or more maps. For each valid map, it prints the map again after marking the biggest square. For each invalid map, it prints map error to the error output.

Read

Open each file argument, or read from stdin when no argument is passed.

Validate

Check the header, characters, line count, line width, and final newlines.

Solve

Find the largest square. If there is a tie, choose the highest one, then the leftmost one.

This tutorial explains the strategy and the allowed C functions. It does not give a full BSQ implementation, so you still practice the real exam logic yourself.

Map Format

In this subject file, the first line is space separated. It tells you the number of map lines, the empty character, the obstacle character, and the full character.

Example input

9 . o x
...........................
....o......................
............o..............
...........................
....o......................
...............o...........
...........................
......o..............o.....
..o.......o................

Header meaning

  • 9: the map has 9 rows.
  • .: empty cells can be used in the square.
  • o: obstacle cells block the square.
  • x: full cells are used to draw the answer.

Validation Checklist

A strong BSQ solution fails fast on bad input and frees memory before moving to the next map.

Header checks

  • The line count exists and is greater than zero.
  • The empty, obstacle, and full characters all exist.
  • Those three characters are different from each other.
  • The three map characters are printable characters.

Map checks

  • There is at least one row and at least one column.
  • Every row has exactly the same width.
  • Every row ends with a newline in the input.
  • Every cell is either the empty character or the obstacle character.
  • The real number of rows matches the header number.
Print map error with fprintf(stderr, "map error\n");, not to standard output.

The Solving Idea

The usual BSQ technique is dynamic programming. Instead of trying every square directly, store the biggest square size that can end at each cell.

Rule

if cell is obstacle: dp[row][col] = 0
else if row == 0 or col == 0: dp[row][col] = 1
else: dp[row][col] = 1 + min(top, left, top_left)

When you find a bigger value, remember its size and bottom-right position. If values tie, keep the first one found while scanning top to bottom, left to right.

Why the tie rule works

If you scan rows from top to bottom and columns from left to right, the first square of a given size is already the highest, then the leftmost. Only update your best answer when the new square is strictly bigger.

  1. Build or update a DP grid while reading the map.
  2. Track best size, best row, and best column.
  3. After solving, replace the matching cells in the original map with the full character.
  4. Print each row to stdout.

Allowed Functions

These examples are intentionally small and generic. They show how each tool behaves without solving BSQ for you.

Function Use it for Important return value Useful notes
malloc Allocate memory when you know the needed byte count. Returns a pointer, or NULL if allocation fails. The memory is uninitialized. Write values before reading from it.
calloc Allocate memory initialized to zero. Returns a pointer, or NULL. Good for arrays of numbers or pointers that should start as zero or NULL.
realloc Resize an existing allocation. Returns the new pointer, or NULL. Use a temporary pointer. If it fails, the old pointer is still valid. Do not overwrite it too early.
free Release memory you allocated. No return value. Calling free(NULL) is allowed. Only free pointers from allocation functions, and free each allocation once.
fopen / fclose Open and close files as FILE * streams. fopen returns NULL on failure. fclose returns 0 on success. Use "r" for reading. After fclose, the stream pointer must not be used again.
getline Read one full line from a stream, growing the buffer when needed. Returns the number of characters read, or -1 at EOF/error. The returned line usually includes the final newline. The buffer must be freed.
fscanf Parse formatted input from a stream. Returns how many items were successfully read. Whitespace in the format matters. %c reads one raw character.
fputs / fprintf Write strings or formatted output to stdout, stderr, or a file. fputs returns a non-negative value on success. fprintf returns characters written, or a negative value. fputs does not add a newline. fprintf is better for variables.
errno Inspect some library errors after a failed call. It is a variable, not a function. Check it after a function reports failure. It is for debugging or decisions, not automatically for exam output.

Before calling

  • Know who owns the memory or file stream.
  • Know which return value means success.
  • Initialize pointers to NULL before cleanup-heavy code.
  • Keep sizes in size_t when they represent byte counts or buffer capacity.

After calling

  • Check the return value immediately.
  • Do not read from uninitialized memory.
  • Do not use a closed file stream.
  • Free buffers created by malloc, calloc, realloc, or getline.

Headers and types

  • <stdlib.h>: malloc, calloc, realloc, free.
  • <stdio.h>: FILE, streams, getline, fscanf, output functions.
  • <errno.h>: errno.
  • <sys/types.h>: often used for ssize_t.

Good cleanup pattern

Initialize pointers, clean what you own, and return only after releasing memory.

int result;
char *buffer;

buffer = NULL;
buffer = malloc(20);
if (buffer == NULL)
{
    free(buffer);
    return (1);
}
/* use buffer here */
result = 0;

free(buffer);
return (result);

malloc

Use malloc when you need a buffer and you know the number of bytes.

stdlib.hremember free
char *name;

name = malloc(6);
if (name == NULL)
    return (1);
name[0] = 'h';
name[1] = 'e';
name[2] = 'l';
name[3] = 'l';
name[4] = 'o';
name[5] = '\0';
fputs(name, stdout);
free(name);
  • Success: you get a block of memory, but its contents are random.
  • Failure: you get NULL; do not write through it.
  • Useful habit: allocate count * sizeof(type), not a guessed byte number.
Array example 
int *values;
int count;
int i;

count = 5;
values = malloc(count * sizeof(int));
if (values == NULL)
    return (1);
i = 0;
while (i < count)
{
    values[i] = i * 10;
    i++;
}
free(values);

calloc

calloc is useful when zero is a safe initial value for every element.

stdlib.hzero-filled
int *scores;
int i;

scores = calloc(4, sizeof(int));
if (scores == NULL)
    return (1);
i = 0;
while (i < 4)
{
    fprintf(stdout, "%d\n", scores[i]);
    i++;
}
free(scores);
  • Success: every byte starts at zero.
  • Failure: returns NULL, same as malloc.
  • Useful habit: use it for arrays where zero means "empty" or "not counted yet".
Pointer array example 
char **words;
int count;

count = 3;
words = calloc(count, sizeof(char *));
if (words == NULL)
    return (1);
/* words[0], words[1], words[2] are all NULL */
free(words);

realloc

Use a temporary pointer so you do not lose the old allocation when resizing fails.

stdlib.hresize memory
char *buffer;
char *tmp;

buffer = malloc(8);
if (buffer == NULL)
    return (1);
tmp = realloc(buffer, 32);
if (tmp == NULL)
{
    free(buffer);
    return (1);
}
buffer = tmp;
free(buffer);
  • Success: you must use the returned pointer from now on.
  • Failure: the old pointer is still valid and still must be freed.
  • Useful habit: grow capacity by doubling it instead of resizing by one each time.
Growing array example 
int *numbers;
int *tmp;
int capacity;

capacity = 4;
numbers = malloc(capacity * sizeof(int));
if (numbers == NULL)
    return (1);
capacity = capacity * 2;
tmp = realloc(numbers, capacity * sizeof(int));
if (tmp == NULL)
{
    free(numbers);
    return (1);
}
numbers = tmp;
free(numbers);

free

Free every allocation once. Setting the pointer to NULL after freeing can prevent accidental reuse.

stdlib.hcleanup
char *line;

line = malloc(100);
if (line == NULL)
    return (1);
/* use line here */
free(line);
line = NULL;
  • Success: there is no return value; the memory is released.
  • Danger: double-free, freeing stack memory, or using memory after free is undefined behavior.
  • Useful habit: when freeing a list of pointers, free the inside allocations first.
Array of strings cleanup 
char **lines;
int i;

lines = calloc(3, sizeof(char *));
if (lines == NULL)
    return (1);
lines[0] = malloc(10);
lines[1] = malloc(10);
lines[2] = malloc(10);
if (lines[0] == NULL || lines[1] == NULL || lines[2] == NULL)
{
    i = 0;
    while (i < 3)
    {
        free(lines[i]);
        i++;
    }
    free(lines);
    return (1);
}
i = 0;
while (i < 3)
{
    free(lines[i]);
    i++;
}
free(lines);

fopen and fclose

Open a file, check the returned stream, and always close it when you are done.

stdio.hFILE *
FILE *file;

file = fopen("notes.txt", "r");
if (file == NULL)
{
    fprintf(stderr, "cannot open file\n");
    return (1);
}
/* read from file here */
if (fclose(file) != 0)
    fprintf(stderr, "close failed\n");
  • fopen success: returns a usable FILE *.
  • fopen failure: returns NULL; do not call getline, fscanf, or fclose on it.
  • fclose failure: returns a nonzero value, often because buffered output could not be flushed.
  • Useful habit: close only files you opened. Do not close stdin unless you have a special reason.
Use file or stdin 
FILE *input;
int should_close;

input = stdin;
should_close = 0;
if (argc > 1)
{
    input = fopen(argv[1], "r");
    if (input == NULL)
        return (1);
    should_close = 1;
}
/* read from input here */
if (should_close && fclose(input) != 0)
    return (1);

getline

getline can allocate the buffer for you if line is NULL and cap is zero.

stdio.hsys/types.h
char    *line;
size_t  cap;
ssize_t len;

line = NULL;
cap = 0;
len = getline(&line, &cap, stdin);
if (len == -1)
{
    free(line);
    return (1);
}
fprintf(stdout, "read %zd chars\n", len);
free(line);
  • Success: returns the number of characters stored, including the newline if one was read.
  • EOF: returns -1 when there is no more input.
  • Error: also returns -1; errno can help you debug the difference.
  • Useful habit: reuse the same line and cap in a loop, then free once at the end.
Strip newline 
if (len > 0 && line[len - 1] == '\n')
{
    line[len - 1] = '\0';
    len--;
}
Read until EOF 
char    *line;
size_t  cap;
ssize_t len;

line = NULL;
cap = 0;
while ((len = getline(&line, &cap, stdin)) != -1)
    fprintf(stdout, "line length: %zd\n", len);
free(line);

fscanf

Always check how many values were read. A partial match means the input is not what you expected.

stdio.hformatted input
int  amount;
char symbol;

if (fscanf(stdin, "%d %c", &amount, &symbol) != 2)
{
    fprintf(stderr, "bad input\n");
    return (1);
}
fprintf(stdout, "amount=%d symbol=%c\n", amount, symbol);
  • Full success: return value equals the number of conversions you asked for.
  • Partial success: return value is smaller; some variables may already be changed.
  • EOF before reading: returns EOF, which is normally -1.
  • Useful habit: use a leading space before %c when you want to skip whitespace.
  • Trap: after fscanf, the rest of the line may still be waiting for the next read.
Raw char vs skipped whitespace 
char raw;
char visible;

if (fscanf(stdin, "%c", &raw) != 1)
    return (1);
if (fscanf(stdin, " %c", &visible) != 1)
    return (1);
Check exact conversion count 
int hour;
int minute;

if (fscanf(stdin, "%d:%d", &hour, &minute) != 2)
{
    fprintf(stderr, "bad time\n");
    return (1);
}

fputs

fputs writes a string exactly as given. Add \n yourself when needed.

stdio.hstring output
if (fputs("hello\n", stdout) < 0)
{
    fprintf(stderr, "write failed\n");
    return (1);
}
  • Success: returns a non-negative value.
  • Failure: returns EOF; output may be incomplete.
  • Useful habit: use it for already-built strings, not for numbers or formatting.
Write to a file stream 
FILE *out;

out = fopen("result.txt", "w");
if (out == NULL)
    return (1);
if (fputs("saved\n", out) < 0)
{
    fclose(out);
    return (1);
}
if (fclose(out) != 0)
    return (1);

fprintf

Use fprintf when you need formatted output or when you must write to stderr.

stdio.hformatted output
int row;
int col;

row = 3;
col = 7;
fprintf(stdout, "row=%d col=%d\n", row, col);
fprintf(stderr, "map error\n");
  • Success: returns how many characters were written.
  • Failure: returns a negative value.
  • Useful habit: write normal program results to stdout and error messages to stderr.
  • Common formats: %d for int, %c for char, %s for strings, %zu for size_t, %zd for ssize_t.
Check output failure 
int value;

value = 42;
if (fprintf(stdout, "value=%d\n", value) < 0)
{
    fprintf(stderr, "could not write output\n");
    return (1);
}

stdin, stdout, stderr

These are already-open streams: input, normal output, and error output.

stdio.hstreams
char *line;
size_t cap;

line = NULL;
cap = 0;
if (getline(&line, &cap, stdin) != -1)
    fputs(line, stdout);
else
    fprintf(stderr, "nothing to read\n");
free(line);
  • stdin is where input comes from when no file is given or when using shell pipes.
  • stdout is for correct program output.
  • stderr is for errors and diagnostics. It is separate from normal output.
  • Useful habit: keep required output clean. Debug text should go to stderr or be removed.
Pipe-friendly program shape 
FILE *input;

input = stdin;
/* This works with:
   ./program
   echo hello | ./program
   ./program < input.txt
*/

errno

errno may hold an error number after a library call fails. Do not use it before checking failure first.

errno.herror number
FILE *file;

errno = 0;
file = fopen("missing.txt", "r");
if (file == NULL)
{
    fprintf(stderr, "open failed, errno=%d\n", errno);
    return (1);
}
fclose(file);
  • Useful for: understanding why calls like fopen, getline, or allocation failed.
  • Not useful for: deciding that an error happened before checking the function return value.
  • Important: successful functions do not have to reset errno to zero.
  • Exam habit: if the subject requires exact text, print exact text, not errno debugging output.
Correct errno timing 
errno = 0;
file = fopen("data.txt", "r");
if (file == NULL)
{
    fprintf(stderr, "fopen failed with errno=%d\n", errno);
    return (1);
}
fclose(file);

Multiple files

When there are several arguments, process each stream separately and print a blank line after each result or error.

argv loopexam behavior
int i;

i = 1;
while (i < argc)
{
    fprintf(stdout, "processing %s\n", argv[i]);
    if (i + 1 < argc)
        fputs("\n", stdout);
    i++;
}
  • Each file should be opened, processed, closed, and cleaned independently.
  • If one file is invalid or cannot open, continue with the next one when the subject asks for that behavior.
  • Do not keep old state between files unless you intentionally reset it.
Independent file loop 
int i;
FILE *file;

i = 1;
while (i < argc)
{
    file = fopen(argv[i], "r");
    if (file == NULL)
        fprintf(stderr, "error\n");
    else
    {
        /* process file here */
        fclose(file);
    }
    i++;
}

Recommended Workflow

Build the program in small parts. BSQ gets much easier when parsing, validation, solving, drawing, and cleanup are separate responsibilities.

  1. Create a structure that stores width, height, characters, and the map rows.
  2. Write a function that reads the header and rejects invalid characters.
  3. Write a function that reads all rows, checks row width, and stores them.
  4. Write the dynamic-programming solver and only store the best square position.
  5. Write a drawing function that fills the chosen square in the map.
  6. Write a printing function that sends rows to stdout.
  7. Write cleanup functions and call them on both success and failure.
A clean mental model: input creates a map, validation protects the solver, the solver finds coordinates, drawing changes the map, output prints it, cleanup releases everything.

Common Mistakes

Input bugs

  • Accepting rows with different lengths.
  • Forgetting that getline keeps the newline in the buffer.
  • Printing map error to stdout instead of stderr.
  • Not handling the no-argument case with stdin.

Memory bugs

  • Losing the original pointer after a failed realloc.
  • Freeing only the array of rows, not each row inside it.
  • Returning early on an error without closing the file.
  • Updating the best square on equal size and breaking the top-left tie rule.
